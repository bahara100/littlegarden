# 작은 쉼표 · Little Pixel Garden

마름모 시점의 **2D 도트 놀이터** 싱글플레이 웹 게임입니다. 친구들이 스스로 산책하고 벤치·그네를 이용하며, 나는 놀이터를 꾸미고 친구에게 지시합니다. 화면은 Phaser 4로 그리고(`src/phaserGarden.ts`), 길찾기·생활·꾸미기·저장 규칙은 화면과 분리해 공유합니다. `?renderer=canvas`를 붙이면 예전 Canvas 2D 화면으로 열립니다.

전체 개발 흐름과 아직 빠진 부분은 [개발 흐름 점검표](docs/GAME_DEV_FLOW.md)에 정리했습니다.

## 실행

Node.js 24 LTS와 npm을 준비한 뒤 프로젝트 루트에서 실행합니다.

```sh
npm.cmd ci
npm.cmd run dev
```

게임: http://127.0.0.1:5173/

Windows PowerShell에서는 실행 정책을 바꾸지 않고 `npm.cmd`를 쓰면 됩니다. macOS/Linux에서는 `npm`을 사용하세요. 로그인·게임 서버·환경 변수 없이 열리며, 실행 중 외부 이미지를 요청하지 않습니다(웹 폰트 실패 시 기본 폰트).

## 구현한 기능

- 2:1 마름모 투영의 도트 놀이터, 줌과 화면 이동, 배치 그리드 표시 전환. 캐릭터와 기구 아래 그림자는 그리지 않습니다.
- 홍련(팬 도트)과 오리지널 친구 모모·루루.
  - 홍련: 승인된 SD 대기·걷기 4방향(SE·NE 원본, SW·NW는 좌우 반전), 방향당 4컷·6 FPS. 걸은 거리만큼만 컷이 넘어가 발이 미끄러지지 않습니다. 앉기 그림은 아직 없어 기구 이용 중에는 대기 그림을 씁니다.
  - 모모·루루: 공통 몸체 SE V20·뒤 걷기 팔 수정 NE V4를 적용한 의상 V3. 뒤 팔을 반대 스윙/중간 통과로 고쳤고 머리·치마 밑단·다리와 앞 걷기/중심을 맞춘 대기는 유지합니다. 방향당96×96·4컷·6 FPS, SW/NW는 컷별 반전입니다. [제작 기록](docs/art/pixel/garden-friends-base-walk-v3/README.md), 검수 페이지 `/friends-base-walk-v1/index.html`.
- 친구 선택 후 **친구 가까이 보기**로 확대해 따라보기. ⌖ 버튼으로 전체 시점 복귀, 화면을 드래그하면 따라보기 해제. 꾸미기에 들어가면 전체 시점으로 돌아갑니다.
- 장애물과 맵 경계를 피하는 A* 경로 탐색. 바닥 칸의 가운데 줄을 따라 걷고 가운데에서 꺾으며, 클릭한 칸의 가운데에 멈춥니다(가운데가 장애물에 너무 가까우면 클릭한 지점). 캐릭터끼리는 부드럽게 간격을 조정하며 지나갑니다.
- 자율 산책과 빈 기구 선택, 접근 중 좌석 예약, 벤치 2석·그네 1석 이용, 하차 후 자율 생활 복귀.
- 친구끼리 반응: 자유롭게 놀던 두 친구가 마주치면 서로 보고 ♡로 인사한 뒤 ···/♪를 주고받아요. 벤치에 친구가 앉아 있으면 옆자리에 같이 앉고(방금 내린 벤치에는 다른 일을 하기 전까지 다시 앉지 않아요), 산책하는 친구를 따라 걷기도 해요. 지시를 받은 친구는 멈추지 않아요.
- 바닥 클릭으로 이동, 기구 클릭 또는 이용 버튼으로 이용 지시, 인사·자유 행동·내려오기.
- 예약·이용 중인 좌석 상태와 이름, 각 친구의 현재 행동 표시.
- 그네: 누가 타면 발판·줄·탑승자가 함께 흔들리고, 내리면 잦아들어 멈춥니다. 빈 그네는 움직이지 않습니다. 기기에서 "움직임 줄이기"를 켜면 흔들지 않습니다.
- 쓰다듬기: 친구를 두 번 빠르게 누르거나(더블탭) **쓰다듬기** 버튼을 누르면 ♡를 띄우며 기뻐하고 친밀도(♥, 최대 99)가 1 오릅니다. 친밀도는 놀이터와 함께 저장·백업됩니다.
- 하루 시간 흐름: 10분에 하루가 지나며 아침·오후·저녁·밤에 맞춰 화면 색이 바뀌고 오른쪽 위에 시각이 보입니다. 밤에는 친구들이 벤치를 더 찾고 더 오래 쉬어요. 설정의 **하루 시간 흐름**을 끄면 오후에 멈춥니다.
- 놀이터 꾸미기(배치·회전·이동·보관)와 브라우저 저장, 파일 백업. 기구·장식·길 타일·피크닉 깔개는 바닥 칸에 맞춰 놓이고(벤치 3×2, 그네 3×3, 나무 1×1 칸). 칸 정렬 전에 저장한 배치는 불러올 때 칸에 맞춰 옮깁니다. 꾸미는 중에는 **되돌리기/다시 하기**(Ctrl+Z / Ctrl+Y, 최대 50단계)를 쓸 수 있어요.
- 보기 설정 기억: 배치 그리드, 확대 배율, 마지막으로 고른 친구, 하루 시간 흐름, FPS 표시를 이 브라우저에 기억합니다(백업 파일에는 넣지 않습니다).
- 휴대폰·태블릿: 두 손가락으로 벌리고 오므려 확대·축소, 손가락 크기에 맞춘 버튼, 좁은 화면용 한 줄 배치.
- FPS 표시: 설정의 **FPS 표시** 스위치로 화면 오른쪽 위에 초당 그린 횟수를 켜고 끕니다.
- 지역 고르기 (기본틀): 지도 왼쪽 위 이름표(LITTLE GARDEN 01)를 누르면 지역 목록이 열립니다. 지금은 01 작은 정원과 02 온천 마을이 있고, 온천 마을은 그림을 준비 중이라 바닥 색(돌바닥·나무 데크 길)만 바뀝니다. 배치·친구는 지역과 상관없이 같습니다. 고른 지역은 브라우저에 기억합니다. 새 지역은 `src/regions.ts`에 한 줄을 더합니다.
- 사계절 (기본틀): 지역 이름표 옆 계절 버튼(✿ 봄 ▾)으로 봄·여름·가을·겨울을 고릅니다. 지금은 바닥 색만 바뀝니다(봄: 그대로 + 분홍 꽃잎, 여름: 짙은 초록, 가을: 노란 바닥, 겨울: 눈 덮인 흰 바닥). 모든 지역에 적용되고 고른 계절은 브라우저에 기억합니다. 계절별 나무·꽃·눈 그림은 나중에 넣습니다(`src/seasons.ts`).
- 노래 (기본틀): 지도 오른쪽 위에 노래 제목이 오른쪽에서 왼쪽으로 흐르고, ☰ 목록에서 노래를 골라 재생·일시정지·멈출 수 있습니다. 한 곡이 끝나면 다음 곡이 이어집니다. 아직 노래는 없어 "노래 준비 중"이 흐릅니다. 노래는 `public/music/`에 파일(영문·숫자·`-_.` 이름)을 넣고 `src/music.ts`의 `TRACKS`에 한 줄을 더합니다.

아직 없는 것: 실제 노래·효과음, 온천 마을 전용 그림, 인사·쓰다듬기 전용 그림, 휴대폰 실기기 검증(두 손가락 확대는 브라우저 흉내로만 확인), 멀티플레이. 자세한 목록은 [점검표](docs/GAME_DEV_FLOW.md)에 있습니다.

기구 이용 중에는 먼저 내려온 뒤 이동·인사를 지시할 수 있습니다. 기구 위 캐릭터를 누르면 그 캐릭터가 선택되므로, 기구가 가려지면 패널의 이용 버튼을 사용하세요. 지시가 끝나면 잠시 쉬었다가 자동 생활로 돌아갑니다.

처음 입장하면 홍련과 모모는 벤치, 루루는 그네를 먼저 이용합니다. 이후에는 기구와 산책을 번갈아 선택합니다. 저장된 배치가 있으면 이를 복원하고 안전한 위치에서 생활을 다시 시작합니다. 이동 경로·좌석 예약·오프라인 시간 진행은 저장하지 않습니다. 브라우저 탭이 숨겨지면 시뮬레이션을 일시 정지합니다.

## 놀이터 꾸미기

1. 화면 상단 **놀이터 꾸미기**를 누릅니다. 생활은 멈추고 친구들은 잠시 쉬어요.
2. 목록에서 새 기구를 고르거나 기존 기구/장식을 클릭합니다.
3. 마우스로 원하는 위치를 가리킨 뒤 **바닥을 클릭해 위치를 고정**하거나 **가로/세로 위치**를 입력합니다. 0.5 단위로 맞춰집니다. 고정한 후에는 마우스를 움직여도 위치가 유지되며, 바닥의 다른 곳을 클릭하면 위치를 바꿀 수 있습니다.
4. **90° 회전**(또는 R), **여기에 놓기**, **이동**, **보관**을 사용합니다. 빨간 미리보기에서는 이유를 확인하고 위치를 바꿉니다.
5. **변경사항 적용**을 누르면 새 배치에서 친구들이 다시 놉니다. 좌석 예약을 비우고 안전한 위치에서 시작합니다.

- **배치 취소** 또는 ESC: 현재 미리보기만 취소합니다. 기존 기구 이동 전 위치가 유지됩니다.
- **전체 변경 취소** 또는 상단 **꾸미기 취소**: 편집을 시작하기 전 배치로 돌아갑니다. 원래 생활 상태도 이어집니다.
- 보관함의 **다시 놓기**로 같은 기구를 복원합니다. 별도 구매/재화는 없습니다.
- 벤치·그네를 여러 개 추가할 수 있고 좌석은 서로 독립적입니다.
- 경계 밖, 기구 겹침, 접근/하차 공간과 중앙 통로 차단은 거부합니다.
- 길 타일은 가구 아래에 놓을 수 있지만 타일끼리 겹치지는 않습니다. 피크닉·안내판은 고정입니다.
- 기구/장식은 보관함을 포함해 최대 160개입니다. 나무는 수관 대신 바닥 영역으로 배치를 판단합니다.
- **변경사항 적용** 시 배치와 보관함을 자동 저장합니다. 적용하지 않은 편집 초안은 저장하지 않습니다.

## 저장과 백업

- 다음 접속 또는 새로고침 시 같은 브라우저의 저장된 놀이터를 자동 복원합니다.
- 놀이터 아래 **파일로 백업**으로 적용된 배치·보관함·친밀도를 JSON 파일로 내려받습니다.
- 저장 형식은 버전 2입니다. 예전(버전 1) 저장과 백업은 불러올 때 단계별로 고쳐 쓰고(친밀도 0으로 시작), 더 새로운 버전의 파일은 거부합니다. 형식을 바꿀 때는 `persistence.ts`의 `MIGRATIONS`에 한 단계를 더합니다.
- **백업 불러오기**로 파일을 고르고 배치/보관 개수를 확인한 뒤 적용합니다. 잘못된 형식·버전·종류·좌표·중복 ID·개수 초과·겹침·통로 차단은 거부합니다. 최대 파일 크기는 200KB입니다.
- **초기 배치로**는 확인 후 배치와 보관함을 기본값으로 바꾸고 저장합니다. 되돌리려면 이전 백업 파일이 필요합니다.
- 불러오기와 초기화는 꾸미기를 마친 뒤 사용할 수 있습니다. 백업은 편집 중에도 적용된 배치만 담습니다.
- localStorage를 사용하며 접속 주소(프로토콜·호스트·포트)와 브라우저별로 별도 저장됩니다. 개발 주소의 배치를 공개 사이트로 옮기려면 백업 파일을 이용하세요.
- 사이트 데이터 삭제 시 저장도 사라집니다. 시크릿 모드·저장 공간 제한에도 대비해 파일 백업을 보관하세요. 서버/계정 동기화는 없습니다.
- 저장 실패는 화면에 알리고 현재 배치를 유지합니다. 읽을 수 없는 저장 데이터는 자동 덮어쓰지 않으며, 기본 놀이터를 표시합니다. 새 배치 적용·백업 불러오기·초기화 시 새로 저장합니다.
- 저장 범위는 기구·장식 배치와 보관함입니다. 카메라·그리드 설정과 캐릭터의 현재 행동은 저장하지 않습니다.

## 검사와 빌드

```sh
npm.cmd run check
npm.cmd test
npm.cmd run build
```

테스트는 `tests/life/` 아래에 있습니다(생활·친구 반응, 꾸미기, 저장/백업, 마름모 투영·가림 순서, 홍련·친구 걷기 시트와 재생). 경로·예약·10분 분량의 자율 생활·배치 검사·저장 복원·손상 파일·저장 실패를 확인합니다. 10분은 빠르게 계산한 시뮬레이션 시간이며 실제 기기 성능 측정이 아닙니다. GitHub의 Verify는 이 게임 검사·테스트·빌드만 돌립니다.

빌드 결과는 `apps/client/dist`입니다. GitHub Pages 하위 경로를 위해 상대 base를 씁니다. 첫 화면 코드는 약 45KB이고, Phaser(약 1.4MB)는 화면이 뜬 뒤 따로 불러옵니다(`?renderer=canvas`는 Phaser를 받지 않습니다).

## 배포 (GitHub Pages)

저장소: https://github.com/bahara100/nikke-playground · 게임: https://bahara100.github.io/nikke-playground/

main 브랜치에 push하면 `.github/workflows/pages.yml`이 검사·테스트·빌드 후 자동으로 배포합니다(Settings → Pages → Source: GitHub Actions). `verify.yml`은 push마다 검사합니다.

현재 상태와 주의:

- 저장소는 Public입니다. 코드와 그림이 모두 공개됩니다.
- 빌드(`npm run build`)는 게임용 파일만 남깁니다. `apps/client/public`의 검수 페이지와 예전 그림 이력은 개발 서버에서만 보이고, 빌드된 코드·페이지가 가리키는 `sprites/...` 경로의 파일만 배포됩니다(`apps/client/vite.config.ts`의 gameFilesOnly). 새 그림은 게임 코드가 가리키면 자동으로 함께 배포됩니다. 결과는 약 8MB입니다.
- 홍련은 원작 캐릭터의 팬 도트입니다. 공개 배포 전에 원작의 팬 창작 가이드라인을 확인하세요.

## 구조

- `apps/client/src/main.ts`: 친구 선택, 상태 패널, 이용 명령, 저장 버튼 등 UI 연결.
- `apps/client/src/phaserGarden.ts`: 기본 Phaser 화면. 바닥·기구·캐릭터 그리기, 그네 흔들림, 카메라, 클릭·드래그·꾸미기 연결.
- `apps/client/src/pixelGarden.ts`: `?renderer=canvas`용 Canvas 2D 화면.
- `apps/client/src/simulation.ts`: 화면과 분리된 생활 상태, 좌석 예약, 경로 탐색, 지시 처리.
- `apps/client/src/layout.ts`: 기구 목록, 크기(EQUIPMENT_SCALE), 배치·회전, 좌석·충돌 정의.
- `apps/client/src/editor.ts`: 꾸미기 초안, 미리보기 검사, 보관함, 적용·취소.
- `apps/client/src/persistence.ts`: localStorage 저장과 백업 파일 형식(version 1).
- `apps/client/src/isometric.ts`: 마름모 투영과 클릭 역투영.
- `apps/client/src/scarletApproved.ts`, `scarletDirections.ts`: 홍련 승인 시트, 방향 선택, 거리 기반 걷기 재생.
- `apps/client/src/pixelAtlas.ts`: 친구 도트 시트 로더.
- `apps/client/public/sprites/`: 게임용 그림. 그 밖의 `public/body-*` 폴더는 아트 검수 페이지입니다.
- `tools/art/`: 그림 생성·변환 스크립트.
- `tests/life/`: 현재 게임 테스트.
- `docs/archive/legacy-code-2026-10-17/`: 지운 3D·예전 검수 모드 코드 보관(복구 방법은 그 안의 README).
- `apps/server`, `packages/shared`, `tests/*.test.ts`, `docs/archive/multiplayer-client`, `Dockerfile`: 보존한 예전 멀티플레이 구현. 현재 게임에는 쓰지 않습니다.

예전 멀티 코드의 회귀 검사는 필요할 때만 실행합니다.

```sh
npm.cmd run check:legacy
npm.cmd run build -w apps/server
npm.cmd run test:legacy
```
