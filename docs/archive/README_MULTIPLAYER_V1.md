# 작은 쉼표 · Little Garden

Phaser + Colyseus로 만든 웹 멀티플레이 놀이터 시제품. 자체 제작한 임시 치비 캐릭터를 사용합니다. 니케 공식 이미지·음원·캐릭터 리소스는 포함하지 않습니다.

## 실행

Node.js 24 LTS, npm을 준비한 뒤 저장소 루트에서 실행합니다.

```sh
npm ci
npm run dev
```

- 게임: http://127.0.0.1:5173/
- 게임 서버: http://localhost:2567
- 상태 확인: http://localhost:2567/health

브라우저 두 개 또는 일반 창/시크릿 창에서 접속합니다. 첫 창의 방 코드를 두 번째 창에 입력하면 같은 방에서 플레이할 수 있습니다. 서로 다른 닉네임을 사용하면 구분하기 쉽습니다.

| 조작 | 기능 |
| --- | --- |
| WASD / 방향키 | 이동 |
| E / 기구 이용 버튼 | 가까운 빈 벤치·그네 사용 |
| 1 / 손 흔들기 버튼 | 2초 인사, 3초 재사용 대기 |
| ESC / 내려오기 버튼 | 하차 |

첫 버전은 PC 키보드 조작을 지원합니다. 작은 화면에서도 페이지 크기는 조정되지만 이동용 터치 조이스틱은 아직 없습니다.

## 구현 상태

- 닉네임과 별도 세션 ID, 방 코드 합류, 방당 정원 16명.
- 서버 확정 이동/충돌, 대각선 속도 보정, 입력 순번, 로컬 예측/서버 보정, 타 사용자 보간.
- 벤치 2석과 그네 1석, 거리 검증, 좌석 동시 점유 방지, 탑승 중 이동 제한.
- 그네의 서버 시간 기준 공통 애니메이션, 전체 사용자에게 인사 모션 표시.
- 예기치 않은 연결 종료 시 좌석 해제와 최대 15초 세션 복귀 허용. 서버 재시작은 세션 복구 대상이 아닙니다.
- 입력/닉네임 검증, 메시지 빈도 및 전송 크기 제한.
- 수목/장애물 충돌과 앞뒤 가림. 플레이어끼리는 통과합니다.

## 검사

```sh
npm run check
npm run build
npm test
```

통합 테스트는 빌드된 서버를 별도 포트에서 시작하고 실제 WebSocket 클라이언트 여러 개로 이동·부적절한 입력·거리 밖 탑승 거부·좌석 경쟁·모션·늦은 입장·재연결·방 분리·16명 정원을 확인합니다. 테스트 전에 서버 빌드가 필요합니다. 상세 결과는 [검증 기록](docs/VALIDATION.md)을 참고하세요.

## GitHub Pages 배포

1. 전체 소스를 GitHub 저장소에 올립니다.
2. 아래 방법으로 실시간 서버를 먼저 배포하고 HTTPS 주소를 확보합니다.
3. 저장소 Settings → Secrets and variables → Actions → Variables에 `VITE_SERVER_URL`을 추가합니다. 값은 `https://서버주소`입니다. 브라우저 SDK가 보안 WebSocket으로 연결합니다.
4. Settings → Pages → Source를 GitHub Actions로 설정합니다.
5. main 브랜치 push 또는 Publish game to Pages 워크플로 수동 실행으로 배포합니다.

서버 주소 변수가 없으면 Pages 배포 작업은 건너뜁니다. 서버 비밀키를 클라이언트 환경 변수에 넣지 마세요. `VITE_` 변수는 공개 빌드에 포함됩니다.

프로젝트 하위 경로 배포를 위해 Vite base는 `./`로 설정했습니다. 현재는 단일 페이지라 별도 라우팅 설정이 필요 없습니다.

## 게임 서버 배포

WebSocket 업그레이드와 장시간 Node.js 실행을 지원하는 호스팅이 필요합니다. GitHub Pages는 이 프로세스를 실행하지 않습니다.

일반 Node.js 호스팅에서는 저장소 루트를 작업 폴더로 사용합니다.

```sh
npm ci
npm run build -w apps/server
npm run start -w apps/server
```

또는 Docker를 사용합니다.

```sh
docker build -t little-garden .
docker run --rm -p 2567:2567 -e PORT=2567 little-garden
```

- 호스팅 제공자의 `PORT` 환경 변수를 사용합니다. 기본값은 2567입니다.
- 프록시에서 HTTPS/WSS와 WebSocket 업그레이드를 설정합니다.
- 상태 확인 경로는 `/health`입니다.
- 현재 단일 프로세스/메모리 상태 모델입니다. 서버를 재시작하면 방과 세션이 초기화됩니다. 여러 인스턴스로 늘릴 때는 공유 presence/driver와 라우팅 설계가 추가로 필요합니다.
- 무료 호스팅의 유휴 절전·시간·메모리·트래픽 한도는 제공 업체별로 확인해야 합니다.

## 다음 검증 및 작업

- 16명·30분 부하 테스트와 100~200ms 지연 환경 검증은 아직 수행하지 않았습니다.
- 모바일 터치 조작, 실제 캐릭터 아트 교체, 좌석별 앉기 프레임과 캐릭터 전용 모션 제작.
- 공개 전 접속량 제한, 방 수 상한, 유휴 사용자 정리, 사용자 신고·퇴장 등 운영 정책 적용.
- 니케 IP의 팬게임 제작/배포 허용 범위 확인. 현재 시제품 검증은 자체 임시 에셋으로 진행합니다.
- GitHub 원격 저장소와 호스팅 계정은 아직 연결하지 않았습니다. 배포 설정 파일만 준비되어 있습니다.
