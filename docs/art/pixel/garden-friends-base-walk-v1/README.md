# 모모·루루 공통 몸체 걷기 첫 적용

> **실패 이력:** 사용자가 옷 도트의 깨짐을 지적해 V1을 거부했다. 현재 런타임과 기존 검수 URL은 [의상 수정 V2](../garden-friends-base-walk-v2/README.md)를 사용한다. 아래 자동 검사 기록은 V1의 작화 품질 승인 의미가 아니다.

2026-10-18. 사용자가 NE V3를 승인하고 모든 방향을 모모·루루에 입혀 실제 놀이터에 적용하도록 요청했다. 외형은 첫 적용 검수 대상이다.

- 베이스: SE `garden-body-walk-se-v20`, NE `garden-body-walk-ne-v3`의 전신 4컷씩. 자세를 다시 생성하지 않았다.
- 네 방향: SE/NE 원본 + 컷별 좌우 반전 SW/NW. 96×96, 4컷, 기본 6 FPS, 캐릭터별 최대 32색(투명 포함).
- 머리: 기존 앞 머리·얼굴 원형 재사용. 뒤를 보는 머리만 모모·루루 각 1개를 새로 준비하고 베이스 머리의 높낮이에 맞춰 배치했다.
- 옷: 기존 의상 전체에는 옛 손이 들어 있어 그대로 덮지 않았다. 원래 치마만 재사용하고 베이스 몸의 명암을 의상색으로 바꾼 뒤 칼라·단추·뒤 허리 리본을 더했다. 팔 소매와 손 겹침도 처리했다.
- 대기: 승인된 편한 팔 SE 대기와, 별도로 추가한 공통 NE 대기 한 컷. 걷기 자세를 바꾸지 않는다.
- runtime: Phaser와 Canvas 모두 실제 이동거리로 각자 프레임을 진행한다. 막히면 멈추고 대기/앉기/편집 때 초기화한다. 기존 모모·루루 앉기 그림과 좌석 배치는 유지했다.

## 재사용 효과와 한계

**공통 걷기 8자세 → 두 캐릭터의 32방향별 컷.** 다리 작화를 캐릭터마다 다시 하지 않았고, `motion-*.png`의 y48 이후 알파 실루엣은 원본 베이스와 같다. 같은 접지와 보폭을 두 친구에 공유한다.

단, 이것은 머리·옷을 준비하면 자동으로 어떤 캐릭터든 완성된다는 뜻은 아니다. 이번 두 친구는 같은 체형과 짧은 원피스여서 잘 맞는다. 긴 머리·코트·무기·큰 치마는 앞뒤 가림과 옷자락 움직임을 더 그려야 한다. 원본 머리·치마의 색은 캐릭터별 팔레트로 정리되어 원본과 바이트 동일하지 않다. 치마는 기본 형태를 유지한 초기 보정이며 사용자 눈으로 순환을 검수해야 한다.

## 파일과 재현

`momo/`, `lulu/`에 최종 `walk-{se,sw,ne,nw}.png`, 대기, 원본 8개의 full/motion/costume/head PNG, 실제 시트에서 만든 미리보기/GIF, 편집용 8프레임 `.pxo`, `*-authoring.zip`이 있다. `.pxo`는 완성 전신 1레이어 8컷이며 별도 PNG가 제작용 레이어다. 런타임 관절 리그가 아니다.

1. Pixelorama MCP `eval_gdscript`에서 `tools/art/build-garden-friends-wardrobe-v1.gd` 실행.
2. `python tools/art/package-garden-friends-base-walk-v1.py` — 시트/반전/32색/연결/베이스 실루엣 검사, 런타임 복사, 실제 프레임 미리보기.
3. Pixelorama로 `editor-sheet.png`를 96×96·8프레임으로 가져와 SE 1~4 / NE 5~8 태그, 6 FPS로 `.pxo` 저장.

생성 도구: **image_gen**. 생성은 뒤 머리 원형 2개와 공통 NE 대기 1컷만 사용했다. 걷기는 생성하지 않았다. 원본 `source-back-heads.png`, `source-idle-ne.png`, 정확한 프롬프트는 [뒤 머리](prompt-back-heads.txt), [공통 뒤 대기](prompt-idle-ne.txt)에 보존한다. 원본 AI 이미지는 최종 도트 시트와 다르다.

검수: `/friends-base-walk-v1/index.html`, 실제 게임 `/`, Canvas `/?renderer=canvas`. manifest.json은 승인 베이스와 런타임 PNG SHA256을 기록한다.

## 이번 검증

- 패키징 검사 통과: 실제 프레임과 시트 일치, 셀별 반전 일치, 머리~발 연결, 이진 알파, 캐릭터별 최대32색, 원본 베이스 몸체 실루엣 유지.
- `npm.cmd run check`, `npm.cmd test` (31/31), `npm.cmd run build` 통과. Vite의 기존 대형 번들 경고는 남아 있다.
- 브라우저 비교 화면에서 SE/SW/NE/NW·뒤 대기·재생/정지 확인. Phaser에서 모모 선택/확대/바닥 이동과 기존 앉기 전환, Canvas에서 루루 외형과 기존 앉기 전환 확인. 최종 Phaser 오류 로그 없음.
- `review-browser.jpg`, `game-browser.jpg`는 실제 브라우저 검수 캡처다. 생성 원본을 게임 결과인 것처럼 표시하지 않는다.
