# 모모·루루 의상 수정 V2

2026-10-18. 사용자가 V1의 깨진 옷 도트를 지적했다. 색 치환·기존 치마 일부를 붙인 방식은 소매/허리/치마의 연속된 형태를 만들지 못했다. V1의 기술 검사 통과는 작화 품질 검수가 아니었다.

## 바뀐 작업

- 베이스 걷기 SE V20 / NE V3를 옷 제작용 자세 참고로 고정했다.
- 모모의 살구 원피스/크림 칼라/허리띠, 루루의 초록 소매/보라 원피스/뒤 리본을 **각 자세에 맞는 완성된 의상으로 다시 작화**했다. V1의 치마 띠나 리본 점조각을 붙이지 않는다.
- 생성 이미지에서는 의상 부분만 채택한다. 기존 머리 PNG의 불투명 픽셀은 그대로 덮어 보존하며, 다리와 신발은 승인 베이스의 실제 도트 형태를 보존하고 양말/신발 색과 명암만 바꾼다. y77 이후 최종 알파는 원본 베이스와 같다. 무릎 위는 치마가 가린다.
- 단색 재색칠 대신 옷/신발 전용 팔레트와 음영을 확보했다. 최대64색(투명 포함), 96×96·4컷·6 FPS. 기존 베이스 자체의32색/다리 자세는 변경하지 않았다.
- 대기 의상도 자연스럽게 팔을 내린 별도 정지 자세로 제작했다.
- SW/NW는 최종 SE/NE 전신 컷을 개별 반전한다. 런타임은 전체 프레임을 재생한다.

## 재사용의 실제 범위

기존 머리 원형과 베이스 다리 자세/접지를 재사용한다. **옷은 자세별로 제대로 그려야 한다.** V1처럼 색만 바꾸거나 치마를 고정 띠로 얹는 것이 완성된 캐릭터 제작 방식은 아니다. 생성 의상에는 팔 실루엣 차이가 조금 생길 수 있으므로 전체 보행의 시각적 확인이 필요하다. 생성 결과를 그대로 승인한 베이스 전신과 동일하다고 주장하지 않는다.

## 결과·편집·재현

`momo/`, `lulu/`의 `walk-{se,sw,ne,nw}.png`, `idle-*.png`가 최종 파일이다. 실제 시트 기반 PNG/GIF 미리보기도 포함한다. `.pxo`는 **다리/의상/머리 3레이어·8프레임·6 FPS**이며 별도 레이어 PNG와 `*-authoring.zip`을 보존한다. `native-project-check.png`는 3레이어를 합친 실제 프로젝트 출력이다.

1. Pixelorama MCP에서 `tools/art/build-garden-friends-wardrobe-v2.gd`를 실행한다.
2. `python tools/art/package-garden-friends-base-walk-v2.py`로 결과/반전/머리 보존/발 위치/연결/색 수를 검사하고 실제 런타임에 복사한다.
3. `legs-editor-sheet.png`, `costume-editor-sheet.png`, `head-editor-sheet.png`를 각각96×96·8프레임으로 가져와 `.pxo`로 저장한다.

도구: **built-in image_gen**으로 의상 작화를 생성한 후 Pixelorama에서 도트화·영역 채택·팔레트 정리·원본 머리와 베이스 다리 보존 합성을 했다. Python은 검증·복사·기존 방식의 실제 프레임 미리보기 포장만 한다. 원본 생성 시트는 최종 재생 시트가 아니다.

정확한 프롬프트: [모모](prompt-momo.txt), [루루](prompt-lulu.txt), [대기](prompt-idle.txt). 생성 원본과 편집 입력은 `source-tailored-*.png`, `wardrobe-target-*.png`, `idle-target.png`다.

검수: `/friends-base-walk-v1/index.html`은 이제 V2 표시. 실제 Phaser/Canvas 게임도 `sprites/garden/base-walk-v2/`를 사용한다. 홍련과 기존 모모/루루 앉기 그림, 기구 배치는 변경하지 않았다. 수정본 외형은 사용자 검수 대상이다.

검증: 패키징 검사 통과(16원본+반전, 머리 픽셀/베이스 발 위치 보존, 연결, 이진 알파, 최대64색). Pixelorama 3레이어 프로젝트 실제 출력이 최종 프레임과 일치한다. 테스트31개·빌드(타입 검사 포함) 통과. 브라우저에서 앞/뒤 걷기·뒤 대기와 실제 Phaser 놀이터의 수정 의상을 확인했고 오류 로그는 없었다. `review-browser.jpg`는 최종 재생 PNG를 표시한 브라우저 캡처다. 기존 Vite 대형 번들 경고는 남아 있다.

## 뒤 대기 골반·다리 중심 보정

후속 사용자 지적: 뒤를 보고 서 있을 때 다리가 몸보다 앞에 나와 보였다. 뒤 의상의 허리 중심과 마네킹 다리 중심이 어긋났기 때문이다. **NE 대기의 다리 레이어만 화면 왼쪽으로5px 이동**해 치마 아래 몸 중심에 붙였다. 발 높이/바닥선은 그대로이며 NW 대기도 반전으로 동기화했다. 걷기·앞 대기·머리·의상은 바꾸지 않았다. 이 예외는 대기에만 적용하며, 위의 승인 베이스 발 위치 보존 검증은 걷기에 대한 것이다.

`idle-ne-before-balance.png`, `idle-nw-before-balance.png`는 수정 전 이력. `idle-ne-balance-comparison.png`는 위=수정 전, 아래=수정 후다. `idle-balance-preserved.json`과 패키징 검사가 모든 걷기/앞 대기 SHA256 보존, 뒤 대기 y0..74 및 머리/의상 영역 동일, 발−5px 이동, 발 높이 보존과 정확한 NW 반전을 확인한다. 이동은 y75 아래 다리에만 적용해 위쪽 팔 픽셀에 영향을 주지 않는다.

편집 원본은 `friends-rear-idle-balanced.pxo`(96×96, 모모/루루 2프레임, 다리/의상/머리 3레이어), 각 캐릭터의 `idle-ne-{legs,costume,head}.png`다. 최종 뒤 대기는 이 원본과 같은 합성이다.

## 뒤 대기 머리·목 중심 후속 보정

사용자가 머리도 앞으로 쏠려 있다고 지적했다. 뒷목 중심 x48~49와 옷의 목선 중심 x43~44를 맞추기 위해 **뒤 대기 머리를 x−5px** 옮겼다. 머리의 모든 불투명 픽셀과 색, 크기/높이는 동일하며 잘림이 없다. 다리 보정과 몸통/옷은 그대로다. NW는 최종 NE 반전이다. 걷기와 앞 대기는 바뀌지 않는다.

`idle-ne-before-head-balance.png`는 머리 이동 전, `idle-ne-head-balance-comparison.png`는 위=이전/아래=수정이다. `idle-head-balance-preserved.json`은 옷/다리 레이어 SHA256 보존을 검증한다. 패키징 검사는 최종 뒤 대기 y55 이후 픽셀 보존과 머리 원형의 정확한5px 평행 이동, 전체 픽셀 수/색 보존을 확인한다. 이전 절의 y0..74 보존 기록은 다리 보정 당시의 이력이며, 현재 머리 위치는 이 후속 보정을 따른다. 최신 편집 원본은 `friends-rear-idle-centered.pxo`다.
