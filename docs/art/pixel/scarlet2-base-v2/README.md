# 홍련2 · 원본 색상과 전신 연결 복원 V2

사용자가 첫 AI 원본과128px 결과의 차이를 지적하고, 원본 느낌과 상체–다리 연결을 다시 살려 달라고 했다. V1과 앉기 그림은 보존하고 별도 V2 정지4방향을 만들었다. 아직 새 V2의 사용자 검수 전이며 게임에는 연결하지 않았다.

## 문제와 수정

- V1의 자동48색 팔레트는 비슷한 흰색/어두운 외곽선에 많은 색을 배정해 눈의 갈색과 허리 장비의 보라색을 잃었다. 새64색 팔레트에는 눈·피부·머리·보라 장비·흰 옷·금속·붉은 천의 색 단계를 따로 확보했다. `palette-ramps.json`이 재현 기준이다.
- V1은 원본의 행99 아래 다리를 잘라 베이스 다리로 교체했다. 골반 의상과 다른 다리 형태가 그 경계에서 섞였다. V2는 **한 덩어리로 이어진 원본 전신을 유지**하며 하체를 교체하지 않는다. 기존 원본에 베이스를 참고해 생성된 비율과128px 규격을 유지하지만, 베이스 발의 정확한 픽셀 실루엣을 강제한다는 과거 검사는 V2에 적용하지 않는다.
- 이번에는 새 AI 이미지를 생성하지 않았다. 보관된 첫 AI 초안의 정렬본 `scarlet2-base-v1/aligned-ai-se.png`와 `rear/aligned-ai-ne.png`를 Pixelorama에서 복원했다. 이전과 같은 전체 배율이며 NE 전신은 발 높이를 맞추기 위해 y+1px 이동했다. 두 방향 모두 최하단114행이다.
- Pixelorama에서 완성 전신을 먼저 만들고, 그 후 머리/몸 두 레이어로 나눴다. 두 레이어를 합치면 전신과 정확히 같고 허리·골반·허벅지 사이에 별도 붙임 경계가 없다. SE/NE 각1컷 `.pxo`, SW/NW는 완성 전신 전체 반전이다.

## 확인 자료

검수 페이지: `/scarlet2-base-v2/index.html`. 이전 V1 페이지 상단에도 링크를 더했다.

- `reference-*.png`: 첫 원본을 같은128px로 정렬·축소한 비교 자료. 새 색 제한 전의 원본 색이며 생성 당시 고해상도 원본과 혼동하지 않는다.
- `idle-se/sw/ne/nw.png`: 실제128×128·알파0/255 결과.
- `idle-four.png`, `idle-four-preview.png`: 위SE/SW·아래NE/NW, 실제 시트와 최근접3배 미리보기.
- `details-before-after.png`: 왼쪽 V1/오른쪽 V2의 눈과 허리–다리 부분, 같은 배율의 실제 픽셀.
- `scarlet2-idle-se-v2.pxo`, `scarlet2-idle-ne-v2.pxo`: 2레이어·1프레임 편집 원본.
- `scarlet2-restored-v2.zip`: 네 방향 PNG·편집 원본·팔레트·검사 기록.
- `browser-review.png`, `browser-mobile.png`: 실제 비교 페이지 확인 자료.

## 검증과 재현

`tools/art/restore-scarlet2-original-v2.gd`를 Pixelorama에서 방향별 body/head 파트로 실행한 뒤 PNG/.pxo를 내보낸다. `py tools/art/package-scarlet2-restored-v2.py`가 포장/검증한다.

- V1·앉기·기존 홍련의92개 파일 SHA256 그대로 보존.
- V2 전신 알파/실루엣이 정렬한 원본과 픽셀 단위로 동일: 하체 경계에서 지운 픽셀이 없다.
- 2레이어 합성 동일, 이진 알파,64색 이하, 두 방향 전체 반전 동일.
- 앞 눈 영역의 따뜻한 갈색 분류 픽셀은5→25, 허리 장비 영역의 보라색 분류 픽셀은2→48. 이는 색상 문제의 국소 확인이며 작화 승인이 아니다.
- 브라우저1개로 비교 이미지7개와 상세 확대,4방향 버튼, 배경 전환, 모바일 가로 넘침/페이지 오류 검사를 확인했다. 처음에는 로컬 서버가 꺼져 있어 실행하지 못했고,4185 서버를 다시 켠 뒤 검사를 통과했다.

기존 앉기 V1에 새 머리나 팔레트를 자동으로 덮어쓰지 않았다. 현재 V2는 정지 수정 후보이며 걷기/기구 연결은 별도 단계다.
